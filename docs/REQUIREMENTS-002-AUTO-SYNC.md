## 1. 需求分析（辩证）

### 1.1 需求合理之处

1. 「软件打开且备份目录存在时才出现开关」能降低用户误操作，避免备份目标不可用时给出虚假开启状态
2. 开关式自动备份符合普通用户心智：打开即同步，关闭即停止
3. 源目录操作实时同步到备份目录，适合文档、照片、项目文件等轻量实时副本场景
4. 与已有拔盘容灾需求可联动：移动介质拔盘时暂停队列、恢复后差异扫描、L2 隔离禁止写入

### 1.2 必须澄清和补强的点

| # | 补强点 | 说明 |
| --- | --- | --- |
| 1 | 「实时」不是字节级强一致 | 应定义为事件触发、去抖合并、最终一致。本地磁盘目标可定「空闲 2 秒内开始、小文件 5 秒内完成」，大文件按吞吐，不承诺固定时延 |
| 2 | 开关打开不能只监听未来事件 | 关闭期间、软件未运行期间、介质离线期间的变更会漏。开关打开必须**先做一次差异扫描/对账，再进入实时监听** |
| 3 | 删除是否同步是高风险决策 | 源目录删除若实时同步到备份目录，误删会快速扩散。建议默认「同步删除但备份端保留版本/回收站 N 天」，或默认「删除延迟同步+可恢复」，并允许关闭删除同步 |
| 4 | 备份目录外部被修改怎么办 | 单向同步下备份目录应视为副本。建议默认「以源为准覆盖」并同时检测外部修改告警；可选「检测到外部修改暂停同步」 |
| 5 | 备份目录不能在源目录内 | 否则递归复制、循环事件、容量爆炸。**必须校验路径包含关系** |
| 6 | 临时文件和写入中文件必须处理 | 编辑器临时文件、Office 锁文件、下载中的大文件，不能边写边复制。需等待文件稳定、排除临时文件、复制到临时文件后原子 rename |
| 7 | 开关可见/可用条件要细分 | 软件打开、配对配置存在、备份目录存在可访问、源目录存在、权限足够、介质在线。条件不满足时是隐藏还是禁用要明确 |
| 8 | 开关状态要持久化并可与实际状态分离 | 用户开关「打开」，但介质拔了、目录不可写、L2 隔离时，状态应是「开启-等待/错误/暂停」，不能假装同步中 |
| 9 | 队列和崩溃恢复 | 事件队列要持久化，软件崩溃/重启后能恢复；否则「实时」不可靠 |
| 10 | 资源与背压 | 大量小文件、批量删除、编译输出目录会打爆 IO。需要并发限制、限速、批量合并、排除规则 |
| 11 | 不是双向同步 | 必须明确不处理备份目录到源目录的回写，避免用户误解 |
| 12 | 与容灾模块联动 | 移动介质拔盘时暂停自动同步，记录断点；恢复后差异扫描；L2 禁止写入并告警切换备用介质 |

### 1.3 建议默认策略

| 项 | 默认值 |
| --- | --- |
| 同步方向 | 单向：源目录 → 备份目录 |
| 开启流程 | 先差异扫描，再实时监听 |
| 删除同步 | 默认开启，但备份端进入回收站/版本保留（默认 7 天，可配）；可关闭删除同步 |
| 备份目录外部修改 | 默认以源覆盖并告警；可选暂停 |
| 临时文件排除 | 默认排除 `*.tmp`、`*.swp`、`~$*`、`.DS_Store`、`Thumbs.db` 等，可配置 |
| 符号链接 | 默认不跟随 |
| 大文件 | 等待稳定后复制；复制到临时文件 → fsync → 原子 rename |
| 关闭开关 | 停止监听和同步，保留已有备份；正在复制的文件允许完成或取消，状态明确；再次打开先差异扫描 |

## 2. 背景与目标

在备份软件中为已配置的「源目录 → 备份目录」配对提供自动备份开关。软件打开且备份目录存在时显示开关；用户打开后，对源目录的创建、修改、删除、重命名、移动等操作最终同步到备份目录。

目标是提供**轻量、可靠、可解释**的实时副本能力，优先保证三件事：不丢变更、不破坏已有备份、异常可恢复。

---

## 3. 范围

### 3.1 包含

- 单/多配对目录的自动备份开关
- 开关可见性、可用性、状态展示与持久化
- 开关打开后的差异扫描 + 实时文件系统监听
- 文件/目录创建、修改、删除、重命名、移动的单向同步
- 事件去抖、合并、队列持久化、失败重试、背压限速
- 临时文件排除、写入稳定检测、原子复制、校验
- 与移动介质拔盘容灾模块联动
- 日志、审计、错误提示、最后同步时间、待同步数量

### 3.2 不包含

- 双向同步、冲突合并
- 完整版本历史/快照管理（仅提供删除回收站/有限版本保留作为保护）
- 软件未运行时的后台实时同步（除非后续增加常驻服务/开机启动，作为可选扩展）
- 网络盘/云盘的强实时保证（可降级轮询）
- 备份目录到源目录的恢复向导（可另立需求）

---

## 4. 术语

| 术语 | 定义 |
| --- | --- |
| 配对 | 源目录与备份目录的绑定关系 |
| 自动备份开关 | 控制该配对是否启用实时单向同步的用户开关 |
| 差异扫描 | 遍历源与备份，按大小/mtime/hash 策略找出新增、修改、删除、缺失项 |
| 稳定文件 | 连续两次检测大小和 mtime 不变，且平台能力允许时无独占写句柄 |
| 最终一致 | 事件处理完成后备份目录与源目录一致；不承诺字节级实时 |

## 5. 功能需求

### 5.1 开关显示与可用条件

#### FR-01 开关可见性

- 软件主界面打开、配对配置存在、备份目录存在且可访问时，显示自动备份开关
- 备份目录不存在/不可访问：隐藏开关或显示为禁用并提示「备份目录不可用」；具体由 UI 配置，**默认禁用并展示原因**
- 源目录不存在：开关禁用并提示「源目录不存在」
- 无权限：开关禁用并提示权限不足
- 移动介质离线：开关保留，状态显示「等待介质」，**不显示为同步中**

#### FR-02 开关状态

状态至少包括：

`关闭` / `开启-差异扫描中` / `开启-同步中` / `开启-空闲` / `开启-等待介质` / `开启-暂停` / `开启-错误`

- 开关位置表示**用户意图**；状态文案表示**实际运行状态**
- 开关状态持久化；软件重启后按持久化意图恢复，但需重新校验条件并做差异扫描

#### FR-03 开关操作

- **打开**：校验路径包含关系、权限、备份目录可写；执行差异扫描；完成后进入实时监听。扫描期间显示进度
- **关闭**：停止监听和新事件入队；正在复制的文件允许完成或按配置取消；保留已有备份；清空未处理队列（再次打开靠差异扫描兜底）；记录关闭时间
- **开关打开但条件失效**（介质拔出、L2 隔离、备份目录删除）：自动进入等待/错误/暂停，**不自动关闭用户意图**；条件恢复后差异扫描再继续

### 5.2 同步语义

#### FR-04 单向同步

- 仅源目录 → 备份目录
- 备份目录视为副本，**不接收用户编辑回写**
- 检测到备份目录被外部修改：默认以源为准覆盖并告警；可配置「暂停同步等待用户处理」

#### FR-05 同步操作范围

- 文件创建、内容修改、删除、重命名、移动
- 目录创建、删除、重命名、移动
- 可选保留 mtime、权限；ACL/扩展属性按平台能力标注
- 符号链接默认不跟随，仅记录或跳过；可配置
- 硬链接按普通文件处理或标注不支持

#### FR-06 删除同步与防误删

- 默认同步删除，但备份端删除项进入**回收站/版本保留区**，默认保留 7 天，可配置
- 可配置「不同步删除」，此时源删除后备份保留
- 目录删除按「先子后父」处理；大目录删除可延迟批量执行并展示进度
- 删除操作需记录审计，支持从回收站恢复

#### FR-07 实时监听

- Windows 使用 `ReadDirectoryChangesW`，Linux 使用 `inotify`，macOS 使用 `FSEvents`；递归监听
- 事件去抖合并：同一路径短时间多次事件合并；批量事件按窗口合并
- 排除规则：默认排除临时文件、锁文件、系统文件、备份软件自身临时文件；排除列表可配置
- **备份目录自身必须排除**；禁止备份目录位于源目录内，禁止源目录位于备份目录内造成循环
- 网络盘/不支持可靠监听的介质降级为可配置轮询，并标注「非实时」

#### FR-08 文件稳定性与原子复制

- 文件写入中不复制；等待大小/mtime 稳定，默认静默 500ms~2s 可配
- 复制到备份目录**同分区**临时文件 → fsync → 校验大小（可选 hash）→ 原子 rename 覆盖
- 大文件复制可限速；失败重试指数退避；被独占打开的文件稍后重试并记录
- 复制后保留源 mtime；校验失败重试，连续失败进入错误列表

#### FR-09 差异扫描/对账

- 开关打开、软件重启、介质恢复、长时间暂停后**必须**执行差异扫描
- 扫描策略：默认大小+mtime 快速判断；可配置抽样 hash/全量 hash
- 输出新增、修改、删除、缺失、冲突列表；按策略执行同步
- 扫描期间实时事件进入队列，扫描完成后按序处理，避免漏事件

#### FR-10 队列与背压

- 事件队列持久化到本机；软件崩溃/重启后可恢复
- 队列按配对隔离；同一文件事件合并，保留最后状态
- 并发复制数可配；总限速可配；大量小文件批量处理
- 队列积压超阈值告警，展示待同步数量

#### FR-11 错误处理与重试

- 权限不足、磁盘满、路径过长、文件被占用、介质离线等分类错误
- 可重试错误指数退避；不可重试错误进入错误列表并告警
- 备份目录不可写时暂停同步，**不删除已有备份**；恢复后差异扫描
- 连续失败达到阈值可自动暂停开关实际同步但保留用户意图，提示处理

#### FR-12 与移动介质容灾联动

- 拔盘事件：立即暂停该配对自动同步，持久化队列和断点，状态「等待介质」
- 重新插入：先走只读检测/三态判定；L0/L1 确认后差异扫描再继续；L2 禁止写入并告警切换备用介质
- **自动备份不得绕过容灾模块的隔离和禁止写盘规则**
- 切换备用介质后，按新备份目录重新差异扫描，保留原介质现场

#### FR-13 日志与审计

- 记录开关操作、差异扫描结果、同步操作、删除、重命名、失败重试、回收站恢复、用户配置变更
- 展示最后同步时间、待同步数量、最近错误、当前状态
- 日志脱敏；支持导出诊断包

#### FR-14 UI 与用户提示

- 开关旁显示状态、最后同步时间、待同步数、错误入口
- 首次打开提示：单向同步、删除保护策略、排除规则、备份目录不可手动修改
- 关闭开关提示：将停止实时同步，已有备份保留；再次打开会先对账
- 备份目录不存在/介质离线/L2 隔离时给出明确原因和操作入口

#### FR-15 权限与安全

- 需要读取源目录、写入备份目录权限；权限不足时禁用开关
- 路径规范化，防目录穿越；符号链接默认不跟随；排除备份目录自身
- **单实例运行**，避免多进程同时监听同一配对
- 不长期提权；底层操作最小权限

#### FR-16 多配对与资源限制

- 每个配对独立开关和状态
- 全局并发、限速、队列上限可配；单配对可单独限速
- 多配对同时差异扫描时排队，避免 IO 打爆

## 6. 状态机

```
关闭 → 用户打开 → 差异扫描中 → 同步中/空闲 → 关闭 → 关闭
```

异常分支：

| 触发 | 状态 | 恢复路径 |
| --- | --- | --- |
| 介质离线 | 等待介质 | 恢复 → 差异扫描 → 同步 |
| 备份目录不可写/权限错误 | 错误/暂停 | 恢复 → 差异扫描 |
| L2 隔离 | 暂停-禁止写入 | 人工处理后恢复 |
| 软件退出 | 持久化状态 | 重启后校验条件 → 差异扫描 |

---

## 7. 关键流程

### 7.1 打开开关

校验配对与路径包含关系 → 校验权限和备份目录可写 → 启动监听 → 差异扫描 → 执行同步 → 进入实时监听。

### 7.2 源目录操作

文件系统事件 → 去抖合并 → 稳定性检测 → 入持久化队列 → 复制到临时文件 → fsync → 校验 → 原子 rename → 更新索引/审计 → 状态更新。

### 7.3 删除

源删除事件 → 延迟窗口（可配）→ 备份端移动到回收站/版本区 → 记录审计 → 到期清理。

### 7.4 关闭开关

停止监听 → 处理/取消当前复制 → 清空未处理队列 → 保留备份 → 记录关闭时间。

### 7.5 异常恢复

软件崩溃/重启 → 读取持久化队列和索引 → 校验条件 → 差异扫描 → 补同步 → 进入监听。

## 8. 数据与持久化

| 数据 | 内容 |
| --- | --- |
| 配对配置 | 源路径、备份路径、开关意图、排除规则、删除策略、版本保留天数、限速、并发、校验策略 |
| 同步索引 | 路径、类型、大小、mtime、hash（可选）、最后同步状态、版本/回收站位置 |
| 事件队列 | 事件 ID、路径、类型、时间、重试次数、状态 |
| 审计日志 | 操作、结果、错误、用户确认 |

所有状态本机持久化；移动介质上可写轻量索引作为辅助，**本机为权威**。

## 9. 非功能需求

| 维度 | 要求 |
| --- | --- |
| 性能 | 本地目标小文件空闲 2 秒内开始同步；批量事件合并；限速和并发可配；差异扫描可暂停/继续 |

| 安全 | 路径校验、防循环、符号链接默认不跟随、日志脱敏、最小权限 |
| 兼容性 | Windows/Linux/macOS 能力矩阵；网络盘/不支持监听介质降级轮询并标注 |
| 可用性 | 状态清晰，错误可操作，默认安全策略 |

## 10. 验收标准

1. 软件打开且备份目录存在时显示开关；备份目录不存在时禁用/隐藏并说明原因
2. 打开开关先差异扫描，**关闭期间**新增/修改/删除的文件能被补同步
3. 源目录新建、修改、删除、重命名、移动最终反映到备份目录
4. 写入中大文件不会被边写边复制；完成后原子替换，校验通过
5. 临时文件按排除规则不备份；备份目录位于源目录内时禁止开启
6. 删除默认进入回收站/版本区，可恢复；关闭删除同步后源删除不影响备份
7. 拔盘后状态「等待介质」，队列持久化；重插后按容灾判定和差异扫描恢复
8. L2 隔离时禁止写入并告警，**不因自动备份绕过隔离**
9. 软件崩溃重启后队列和索引可恢复，差异扫描补漏
10. 开关关闭后停止同步，已有备份保留；再次打开先对账
11. 备份目录外部修改按策略覆盖并告警，或暂停等待处理
12. 日志包含开关、同步、删除、错误、恢复记录，诊断包可导出且脱敏

## 13. 与现有实现的关系

现有 v0.1.0 是一次性手动全量备份流程（选目录 → 扫描 → 计划 → 开始），**没有配对概念、没有事件监听、没有增量同步**。以下是与本需求的复用与差距对照，均以代码为依据。

### 13.1 可直接复用的部分

| 需求点 | 现有实现 | 说明 |
| --- | --- | --- |
| 差异扫描（FR-09） | `planner.ts` 五轮判定链：元数据快判 → 大小不同 → 同尺寸哈希 → 按 size 分桶 → 改名配对 | **最大复用点**。判定语义与 FR-09 要求的「大小+mtime 快速判断，可配抽样/全量 hash」高度一致，只需改造为增量可中断并输出可执行动作列表 |
| 同步索引（§8） | `manifest.ts` 记录 `size` / `mtimeMs` / `sha256` / `backedUpAt`，原子写 | 与「同步索引」字段高度重合，仅需增加「最后同步状态」「版本/回收站位置」两个字段 |
| 原子复制（FR-08） | `copyWorker.ts`：`.part` 临时件 → `fsync` → 回读校验 → 原子 rename；并已支持按 1 MiB 分片逐块 SHA-256 比对，只重写受损分片 | 已满足「临时文件 → fsync → 校验 → 原子 rename」主链路；块级复用可直接服务于实时同步的增量写入；仍缺 mtime 保留、限速、退避重试、独占锁检测 |
| 持久化存储层 | `journal.ts` 原子写 JSON 到本机 userData | 事件队列可沿用同一存储层与原子写模式 |
| 符号链接策略 | `scan.ts` 跳过符号链接并计数 `skippedSymlinks` | 与 FR-05「默认不跟随」语义一致 |
| 介质状态与暂停恢复 | `service.ts`：`lost → interrupted → 显式恢复` 流转；恢复需用户确认并重新扫描，续传由工作线程按分片比对完成 | 可作为 FR-12 的挂载点；**注意恢复不再自动续传**，实时同步的介质恢复需自行套用同样的显式确认语义 |
| 校验与重传 | `copyWorker.ts` 校验失败返回 `VERIFY_FAILED` 并**保留临时件**，不再整份重传；下次运行按分片比对只重写受损分片 | 与 FR-08「校验失败重试」一致，且重试代价从「整份」降为「受损分片」 |

### 13.2 纯新增的部分

| 需求点 | 现状 |
| --- | --- |
| 实时监听（FR-07） | 无任何文件监听代码 |
| 事件队列与去抖合并（FR-10） | `journal.ts` 是「任务级快照」，不是事件队列，无重试计数与状态流转 |
| 配对配置持久化（§8） | 无。UI 每次重新选目录，配置只在内存与 localStorage 的主题偏好中 |
| 排除规则配置（FR-07） | `scan.ts` 仅硬编码排除 `.backup-studio` 目录与符号链接 |
| 回收站 / 版本保留（FR-06） | 无 |
| 开关 UI 与状态机（FR-01~03） | 无配对概念与开关 |
| 多配对调度（FR-16） | 单源单目标 |

### 13.3 需要修正的既有实现

| 项 | 现状 | 需求要求 |
| --- | --- | --- |
| **路径包含关系校验** | `service.ts` 直接使用 `sourceRoot` / `targetRoot`，**不做包含关系校验** | FR-07 / FR-15 禁止备份目录位于源目录内，否则递归复制、循环事件、容量爆炸。这是必须新增的硬校验 |
| **单实例** | `main.ts` 未调用 `app.requestSingleInstanceLock()` | FR-15 要求单实例运行，避免多进程同时监听同一配对 |
| **可写性探测会写盘** | **已修复**（REQ-ENG-001 第一阶段）：`media.ts` 的 `probeMedia()` 只做 `stat`/`access`，探测与写入通道已分离 | FR-01 / FR-11 的纯只读探测要求已满足；实时同步若自行探测可写性，应沿用同一实现而非重写 |
| **删除风险闸门不适用于实时路径** | `planner.ts` 对批量孤儿比例 > 30% 等情况挂起二次确认 | 实时路径是逐事件删除，不存在批量孤儿比例。两条删除路径需分开实现：批量对账走闸门，实时删除走回收站保护 |
| **`MAX_ACTIONS` 计划上限** | `planner.ts` 上限 20000 条动作 | 实时事件路径不受此限；仅差异扫描的全量结果需要截断策略与提示 |

## 14. 与 REQ-ENG-001 的依赖关系

| 本需求条目 | 依赖 REQ-ENG-001 的 | 说明 |
| --- | --- | --- |
| FR-12 介质联动 | FR-04 只读检测、FR-07 三态判定器、FR-12 隔离与备用介质切换 | 自动备份的「写入许可」必须由容灾判定器裁决，不得自行判定 |
| FR-09 差异扫描 | FR-06 逻辑健康检测中的分片/索引校验 | 应共用同一套扫描与校验引擎，避免两套判定逻辑漂移 |
| §8 事件队列持久化 | FR-02 双写事务日志、本机日志权威 | 同步队列与容灾账本共用「本机权威、盘上辅助」的存储约定 |
| FR-06 删除保护 | REQ-ENG-001 §3.10 禁止事项第 5 条「禁止废弃唯一完整备份集」 | 实时删除不得覆盖该约束 |
| FR-14 UI 提示 | FR-13 诊断包、FR-07 证据链 | 同步错误提示应能下钻到容灾证据与诊断包 |
| FR-08 原子复制 / 增量写入 | FR-03 分片层（分片级 hash 比对与「只重传受损分片」） | 第二阶段已落地分片级比对，实时同步的小文件高频写入可复用同一条块级校验路径；但块级 hash **未落盘为索引**，FR-08 所需的可恢复索引快照仍缺 |

**硬约束**：自动备份在任何情况下都不得绕过容灾模块的只读、隔离、禁止写盘判定（见 §11 风险项与验收标准第 8 条）。
